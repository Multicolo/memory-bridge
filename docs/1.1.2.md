# 记忆互通 1.1.2 更新日志

**发布日期**：2026-11-09
**上一版**：1.1.1（2026-11-08 18:01 UTC）
**仓库**：https://github.com/Multicolo/memory-bridge
**下载**：https://github.com/Multicolo/memory-bridge/releases/tag/v1.1.2

一句话：**实时同步从「每 20 秒刷一段日志」变成「只在数字变了才说一句」，并且让仓库、exe、源码包里的 `realtime.py` 真正变成同一份。**

---

## 为什么会有这一版

1.1.1 的实时互通沿用「每轮都打印」的写法，常驻一晚日志能涨到 190 KB 左右，翻起来全是同一句「已拉取：记忆 N 条…」。

更麻烦的是：这么长的输出如果挂在 DSH 的后台任务里，任务本身被回收时守护进程也跟着没了 —— 表现就是「明明开着一晚上，早上发现它不跑了，日志里还没有任何报错」。

1.1.2 把这两件事一起解决：**减少输出 + 说明怎么用独立进程跑**。

---

## 改了什么

### 1. 静默模式 `--quiet`

- 只在记忆条数 / 对话条数**发生变化**时写一行：`记忆 119 条 · 对话 238 条`
- 没有变化就一个字都不写（所以一晚上日志从 190 KB 降到几十 KB）
- 不加 `--quiet` 时行为与以前完全一致，老用法不受影响

```bash
python realtime.py --interval 30 --quiet        # 常驻，安静
python realtime.py --once --quiet               # 只跑一轮，适合看状态
```

### 2. 桌面版的「实时同步」开关默认走静默模式

界面里点「实时同步 → 开启」，起的守护进程就是 quiet 的，主界面的运行日志不再被刷屏。想取消就点「停止」，`--stop` 命令行同样有效（pid 记在 `realtime.json`）。

### 3. 推荐用独立进程常驻

这样起的进程不挂在 DSH 的后台任务上，关掉对话窗口也继续跑：

```powershell
Start-Process -FilePath python `
  -ArgumentList "realtime.py","--interval","30","--quiet" `
  -WorkingDirectory "memory\bridge" -WindowStyle Hidden
```

`memory/README.md` 的「实时互通（常驻）」一节已经补了这段示例。

### 4. 三处 `realtime.py` 对齐

1.1.1 的源码包（`memory-bridge-1.1.1-source.zip`）里那份 `bridge/realtime.py` 是旧文件（11,344 B），比 exe 与仓库里的小一圈（11,663 B）—— 等于「下载源码包的人拿到的和 exe 不是一套」。

这版仓库、exe、源码包统一成同一份（12,649 B，含 quiet）。打包流程也改成：**先出源码包 → 再用源码包里的 `bridge/*.py` 回灌仓库与 exe**，避免再漂。

- **单文件版**：直接换掉旧的 `记忆互通.exe`，`config.json` 和 `memory/` 目录原地保留，不用重新配置。

## 已知限制

- **静默模式不会告诉你"拉取失败了"**：失败仍会写日志（`拉取失败：…`），但不影响计数行；排查时先看 `realtime.log` 最后几行。
- **隧道断了不会自动重连**：桥假设本机到面板的通道是通的（SSH 隧道 / 内网直连）。断了就是 `WinError 10061`，恢复后下一轮自动续上。要不要加自动重连还没做，需要的话可以排在 1.1.3。
- **设置窗不预填地址**：故意留空，避免把某个默认地址硬编码进别人机器；地址填错会在「保存并测试」直接报原因。
